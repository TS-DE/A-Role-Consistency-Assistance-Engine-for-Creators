## 三、整改计划（一批一验证）

**原则：一次只动一类，每批改完立刻跑全量离线用例（55 个）。**
结构重构最容易出的不是语法错，是"路径常量没跟着改"——它会静默指向不存在的文件，
直到某天跑评测才炸。

### 批次 A（低风险，建议先做）

```
tests/golden_cases.json      → data/golden/golden_cases.json
tests/golden_holdout.json    → data/golden/golden_holdout.json
tests/golden_holdout_f.json  → data/golden/golden_holdout_f.json
tests/validate_golden.py     → tests/scripts/validate_golden.py
tests/compare_rounds.py      → tests/scripts/compare_rounds.py
tests/audit_leakage.py       → tests/scripts/audit_leakage.py
tools/build_judge_yaml.py    → src/cli/tools/build_judge_yaml.py
```

连带改动：`constants.py` 里 `GOLDEN_JSON` / `HOLDOUT_JSON` 两个常量；
三个脚本里的 `ROOT = Path(__file__).resolve().parent.parent` 要各退一层；
`run_judge.py` 的默认值注释。

### 批次 B（中风险）

```
src/cli/run_judge.py            → src/cli/eval/run_judge.py
src/cli/score_generation.py     → src/cli/eval/score_generation.py
src/cli/cost_report.py          → src/cli/eval/cost_report.py
src/cli/run_graph.py            → src/cli/serve/run_graph.py
src/cli/smoke_loop.py           → src/cli/serve/smoke_loop.py
src/cli/check_observability.py  → src/cli/serve/check_observability.py
```

连带改动：所有 `python -m src.cli.xxx` 的调用示例（README、docs 08/09/10/11、CHANGELOG）。

### 批次 C（高风险，最后做）

```
src/judge/constants.py       → src/judge/core/constants.py     ← PROJECT_ROOT 要改成 parents[3]
src/judge/hit_parser.py      → src/judge/core/
src/judge/quote_validator.py → src/judge/core/
src/judge/aggregator.py      → src/judge/core/
src/judge/chat_model.py      → src/judge/models/
src/judge/langchain_model.py → src/judge/models/
src/judge/env_loader.py      → src/judge/spec/
src/judge/spec_loader.py     → src/judge/spec/
src/judge/prompt_builder.py  → src/judge/spec/
src/judge/evaluator.py       → src/judge/runner/
tests/judge/*                → tests/judge/{core,models,spec,runner}/
```

**特别注意**：`constants.py` 里的 `PROJECT_ROOT = Path(__file__).resolve().parents[2]`
在移动后必须变成 `parents[3]`。这是整批里唯一会"静默失败"的改动——
路径错了不会报错，只会找不到文件。
