## 二、泄漏的三层

| 层 | 是什么 | 实测 | 能修吗 |
| --- | --- | --- | --- |
| **L1 标注泄漏** | `note`/`why`/注释里写着"D05-a 探针，gold = 0""…= 判 1""D12-c 探针，gold = 1" | 原始 yaml 里 **24 行**带探针编号或分数，涉及 **16 个候选编号** | ✅ 能。已生成 `sherlock.judge.yaml`，L1 归零 |
| **L2 例句泄漏** | `example_bad` / `observable_behaviors` 直接就是候选原文 | **6 / 31**（3 条整句 + 3 条整句片段）：D02-a、D05-a、D12-c 整句；D04-b、D07-b、D11-c 首句 | ❌ 不能靠改文件；只能换测试样本 |
| **L3 规则泄漏**（最致命） | 规则是**照着这 31 条写出来的** | 无法用正则量化，但是 100% 的主因 | ❌ 只能靠留出集 |

**L3 的证据在你自己的第二轮里**：D12-c 的依据栏写的是"属于『直接拒绝/逐客 = 1（D12-c）』"——
那个 `（D12-c）` 编号是我写在 yaml 注释里的。**你判对了，但你是从规则里读到的答案，不是从文本推出来的。**

同样，D04-b 你第二轮的依据是"命中 soft：连续两轮以上主动关心对方感受"——那是**另一条** pattern，
不是你该命中的"健康/安危冷嘲"。分数对了，理由错了。**这说明在 L1/L2 存在时，人会先去找编号，而不是先去看文本。**

### 为什么 L2 已经不可逆

看 yaml 里现在的规则是**怎么长出来的**：

| 候选 | 它造就了哪条规则 |
| --- | --- |
| D05-a | 新 hard pattern「把无关细节/职业特征当作罪证」+ rule (4) |
| D12-c | 新 soft pattern「对送来门的委托直接拒绝或逐客」 |
| D07-b | era rule (4)「否定式不豁免」 |
| D04-d | 计数单位 (4)(5)「回指片段、同片段不双计」 |
| D12-a | `observable_behaviors` 第 1 条（原样抄了候选半句） |

**规则和测试样本互为镜像了。** 这时候再让任何模型读这份 yaml 去判这 31 条，它不是在"判"，是在"对答案"。
换 3 个模型也是 100%，换 30 个也是——这只证明规则写清楚了，不证明规则能判没见过的东西。

## 三、这条正好是 `docs/02` 预言的

`docs/02` §二 早就写了 dev / test 分离：

| 集合 | 谁能看 | 用途 |
| --- | --- | --- |

**好消息是你现在真撞上了，而不是在面试现场被问住。** 这句话本身就可以写进项目复盘：

> "我第一版报出 100% 人机一致率，然后做了泄漏审计，发现判定输入里写着 16 个探针编号和 6 条候选原句，
> 而且规则本身就是从这批样本反推出来的。所以我把这 31 条降级为 dev 集，重新设计留出集。"

## 四、拿回一个可信数字：三步，成本 < 1 小时

### 第 1 步：判定输入换成干净文件（已完成）

`data/characters/sherlock.judge.yaml` —— 由 `tools/build_judge_yaml.py` 自动生成：

- 去掉所有 `note` / `why` / `probes` / 注释
- 剔除字符串里的探针编号与分数
- 保留：`persona` / `voice` / `scoring`（聚合+计数）/ `traits`（rule + anti_patterns + exemplars）/ `cross_trait_index` / `knowledge` / `not_ooc`

审计结果：**L1 = 0**（剩下 3 处是误报，`>= 2 -> 0` 这类聚合规则原文）。L2 仍在 6/31 —— 那是数据问题，见第 2 步。

### 第 2 步：写 8 条新候选（**不要给 yaml 看**）

每 trait 一条，句子全新，且**故意复刻同一批"轴"但换皮**，这样才是同分布留出集：

| 新 ID | trait | 设计要点（复刻哪条轴，但不复用任何原句） |
| --- | --- | --- |
| E01 | emotional_restraint | 抒情安慰，但换成"握住他的手"这类肢体动作 |
| E02 | evidence_first | 有细节、无推断链（复刻 D05-a 的轴） |
| E03 | evidence_first | 数据充分但仍说"再等等"（反向：过度谨慎，测误杀） |
| E04 | era_consistency | 否定式提到年代外概念（复刻 D07-b 的轴） |
| E05 | no_glory_seeking | 记者在场，他淡淡把功劳推给苏格兰场（测不误杀） |
| E06 | voice_register | 大男主腔 + 健康冷嘲同现（测计数 (4)(5)） |
| E07 | watson_rapport | 调侃观察力 → 2；改一个字变成人身否定 → 1 |
| E08 | moral_flexibility | 有标准地放人 → 2；放弃标准 → 1 |

> 关键纪律：**先定 8 条题目和 gold，再让模型跑。** 顺序反了就又变成"看答案写规则"。

### 第 3 步：三方盲跑

```
① 你：只读 sherlock.judge.yaml  → 给 8 条打 gold（写完就封存）
② 豆包（或任意模型）：只读 sherlock.judge.yaml + 8 条候选 → 打分
③ 对比：一致率 + κ + 漏杀/误杀
```

≥ 90% 才能说"yaml 已自足、规则可迁移"；< 90% 的分歧照旧是规格书的洞。
**这个数字才是能给面试官看的那个。**

## 五、这轮真正的收获（不是分数）

1. **A03 证明了工程可用性**：yaml 作为 prompt 是**可执行**的——模型能稳定按它产出与 gold 全同的结果。
   这证明"规则可被机器读"，不证明"规则判得准"。两件事，报简历时要分开说。
2. **A03 顺手证明了另一件更值钱的事**：`docs/02` 的 dev/test 分离不是形式主义，是**唯一**能让"准确率"有意义的东西。
3. 你已经有了一条可复现的流水线，而且每一步都留下证据：

```
sherlock.yaml  --build_judge_yaml-->  sherlock.judge.yaml --audit_leakage--> CLEAN(L1)
                                                                    |
候选 + judge.yaml --25 秒--> 打分 --compare_rounds--> 一致率 / κ / 漏杀 / 误杀
```

这四个脚本就是你 B 端方案里"校准协议"的原型：**换客户时换 spec + gold，代码不动。**

## 七、留出集的退役规则（2026-10-27）

A03 那次是**别人**在读答案。这次是**我自己**把答案写进了规则里，过程更值得记：

| 时间 | 事件 |
|---|---|
| 10-26 | 写 E01–E08（留出集），首次盲跑：13/17 = 76.5% |
| 10-27 | 发现 E08-a 稳定判错（把"复述案情"当"指认"）→ **加 `evidence_first` rule(6)** |
| 10-27 | 发现 E06-a 抖动（同一句被两个 trait 各截一段）→ **去重判据改为「同句」** |
| 10-27 | 再跑同一批：**16/17 = 94.1%** |

94.1% 不能报。至少两处修正，是照着这批样本的失败写的 —— 它是"在留出集上训练过一次"的成绩。

**四条规则，写死：**

1. 一批样本一旦被用来改规则，就**降级为回归集**，不再是留出集。
2. 留出集**只跑一次**；跑完不论好坏都封存，不许"再跑一次看看"。
3. 想验证修好的规则，写**下一批**（G01–G08）；不要让被修过的那批复职。
4. **写留出集的人，不能是调规则的人。**

**现在的分工：**

| 集合 | 身份 | 用途 |
|---|---|---|
| `tests/golden_cases.json`（D01–D12） | dev | 调规则、调提示词 |
| `tests/golden_holdout.json`（E01–E08） | **回归集**（已退役的留出集） | 改完规则必须跑，防倒退 |
| `tests/golden_holdout_f.json`（F01–F08） | **留出集**（未跑过） | 只跑一次，跑完封存，用来报数 |

> 一条工程纪律：**留出集的寿命只有一次**。用完就废，这不是浪费，是它唯一能证明"泛化"的方式。
> 你能把这个退役过程讲清楚，比报出 94.1% 值钱得多——因为它证明你知道自己什么时候在骗自己。
