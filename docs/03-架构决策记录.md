# 03 · 架构决策记录（ADR）

> 面试官不会问你"会不会用 LangGraph"，会问你**"为什么用它"**。
> 这份文档就是答案库。每周补一条，比到最后一周凭记忆编要靠谱得多。
>
> 一条 ADR 只回答四个问题：**决策是什么 / 还考虑过什么 / 为什么选它 / 代价是什么**。
> 最后一项最重要——没有代价的决策都是没想清楚的决策。

---

## ADR-001 · 先写规格书与测试集，再写代码

- **状态**：已采纳 　**日期**：2026-10-22
- **决策**：第 0 步不写 FastAPI、不装 LangGraph、不做 RAG。先把"什么算 OOC"变成可判定规则 + 25 条带基准分的用例。
- **备选方案**：
  1. 直接照教程搭 FastAPI + LangGraph 骨架，边跑边补规则。
  2. 先做 RAG（看起来最有技术含量），校验以后再说。
- **为什么选它**：
  1. **校验节点的 prompt 就是规格书的翻译**。规格书没写好，prompt 只能自由发挥，"通过/不通过"没有稳定语义，第二周加 HITL 也没有意义——你都不知道打回的是什么。
  2. **测试集必须先于实现**。最后一周才写的测试集，一定是对着实现结果反向标注的，指标是自证。面试一问"你怎么保证测试集没经过挑选"就崩。
  3. **这一步 AI 不能替我做**。判"福尔摩斯会不会这么做"是领域判断，不是代码活。它恰好是我最缺的那部分——读懂材料、下判断。
- **代价**：头两三天没有一行代码，没有"进度感"，看起来像在磨蹭。
  —— 但这个代价我认，因为它换来了后面所有指标的可信度。

## ADR-006 · 指标口径：OOC 率 = 0 分样本占比，且必须同时报漏杀/误杀

- **状态**：已采纳 　**日期**：2026-10-22
- **决策**：三档打分（2/1/0），OOC 率只数 0 分；同时报告漏杀率与误杀率。
- **为什么**：只报 OOC 率可以靠"全判 0"刷到 0%。必须成对报告，
  才能证明"既拦得住，又不误杀"——这正是企业落地时真正的难点。
- **代价**：标注成本翻倍（要标出"边界分 1"）。
