# 08 · 判定器模块结构（v0.2.1 重构后）

> 这份文档回答一个问题：**为什么代码是这样分层的**。
> 面试被问"你的模块怎么划分的"，答案在这里，不在代码注释里。

## 一、分层与依赖方向

```
src/cli/run_judge.py      入口层：参数解析、进度打印、结果落盘（不含判定算法）
        │
        ▼
src/judge/evaluator.py    编排层：逐 trait 取证 → 聚合 → 完整性标记
        │
        ├── prompt_builder.py     组装提示词（纯函数式，不联网）
        ├── chat_model.py         ChatModel(ABC) + OpenAICompatChatModel(实现)
        ├── hit_parser.py         模型输出 → 结构化命中
        ├── quote_validator.py    引文子串校验、区间定位、落句定位
        └── aggregator.py         ScoreAggregator：命中 → 三档分
                │
                ▼
src/judge/constants.py    常量：路径、档位、超时、重试、失败阈值
src/judge/env_loader.py   .env 读取
src/judge/spec_loader.py  判定输入（judge.yaml）载入
```

依赖只向下：入口层 → 编排层 → 能力层 → 常量。**编排层不认识 urllib，只认识 `ChatModel` 抽象**，
所以换服务商只加一个子类，业务代码不动。

## 二、数据流（一次判定的全过程）

```
候选文本 + 一条 trait
   → PromptBuilder.build()      拼出 messages（含 rule / anti_patterns / exemplars / not_ooc 豁免）
   → ChatModel.complete()       只负责"发出去、拿回来一段文本"
   → HitParser.parse()          容忍 ```json 围栏与前后废话，产出 hits[] + ambiguity[]
   → QuoteValidator.validate()  每条 quote 必须是候选原文的子串，否则整条丢弃（记进 invalid）
   → ScoreAggregator.score()    硬命中→0；soft 按"落句"去重后 ≥2→0、==1→1、否则 2
```

**分数是算出来的，不是模型给的。** 模型只举证，聚合规则在代码里，改一行不用重标 31 条。

## 三、三个刻意的设计决定

| 决定 | 理由 | 代价 |
|---|---|---|
| 分数从 hits 派生 | 分歧可归因到具体 pattern，而不是"你觉得 1 我觉得 2" | 模型必须每次都给引文 |
| 引文强校验子串 | 把"可举证"变成机器可检查；编造引文拿不到分 | 模型改写过的引用会被丢弃（宁可漏） |
| 去重按"落句"而非区间重叠 | 模型引用长短会变，区间随之伸缩，判据跟着抖（E06-a 三轮 0/1/0） | 同一句里的两处违规会并成一条 |

## 四、运行时保护（踩过坑才加的）

1. **preflight**：起跑前先发一次极短请求。网络不通立刻退出，不会安静地跑一小时。
   —— 这是实际事故：整批 136 次调用全部超时，第一行输出要等 8 次调用结束后才出现。
2. **逐 trait 进度行**：每次调用结束就打一行，卡在哪条规则一眼看见。
3. **失败熔断**：连续 8 次失败判 `JudgeAborted`，整批中止。
4. **未完成样本不进分母**：任何一条 trait 失败，这条候选标记 incomplete 且不计入准确率
   —— 缺 trait 的 soft 计数可能恰好等于 gold，那是假通过。
5. **失败补跑**（v0.2.2）：某条 trait 失败后只补跑它，最多 `--missing-retries` 轮，
   不重跑已成功的。实测千问 27B 单次 15–30s，20s 超时会误杀，故超时放宽到 60s 并给每次调用 0.6s 间隔防限流。

## 五、跑法

```bash
# 离线单测（不联网，无需 pytest）
python -m tests.judge.test_aggregator
python -m tests.judge.test_quote_validator

# 只看提示词，不发请求
python -m src.cli.eval.run_judge --cases data/golden/golden_holdout.json --limit 1 --dry

# 正式评测
python -m src.cli.eval.run_judge --fanout --cases data/golden/golden_holdout.json --json-out reports/holdout_run_03.json

# 稳定性实验（同一候选重复 N 次）
python -m src.cli.eval.run_judge --fanout --cases data/golden/golden_holdout.json --ids E05-b,E06-a,E06-b,E08-a --repeat 3 --json-out reports/stability_run_02.json
```

> Windows 下命令一律写成**单行**，不支持 bash 的 `\` 续行。

## 五·补、换后端（成本控制）

`ChatModel` 抽象的第一个实际收益：**换模型只改 `.env`，一行代码不动。**

```ini
# 云端（正式报数用）
JUDGE_BASE_URL=https://api.deepseek.com/v1
JUDGE_MODEL=deepseek-chat

# 本地（开发期调 prompt、跑回归集，零成本无限次）
JUDGE_BASE_URL=http://localhost:11434/v1
JUDGE_API_KEY=ollama
JUDGE_MODEL=qwen2.5:14b
```

成本口径：一轮全量 fanout = 17 条候选 × 8 条 trait = 136 次调用 ≈ 20 万 tokens。
所以**开发期不要用云端全量刷**，用 `--ids` / `--trait` 只跑要改的那几条，或切本地。

旧命令 `python src/judge.py ...` 已废弃（那是个 600 行的单文件，违反 300 行上限）。

## 六、与通用约束的对照

| 约束 | 落点 |
|---|---|
| SRP 单一职责 | 一个文件一个能力：拼提示词 / 发请求 / 解析 / 校验 / 聚合 / 编排 / 入口 |
| OCP 开闭 | 换服务商 = 新增 `ChatModel` 子类，不改编排层 |
| DIP 依赖倒置 | 编排层依赖 `ChatModel` 抽象，外部资源构造注入 |
| 模块化 | `src/` 与 `tests/` 下均无裸文件；每个新目录有 `__init__.py` 且写明职责 |
| 文件与行数 | 最大文件 178 行（`cli/run_judge.py`），其余 19–92 行，均 < 300 |
| 测试 | `tests/judge/test_<被测模块>.py`，按被测域分子目录 |
| 常量收敛 | 路径、档位、超时、重试、熔断阈值全在 `constants.py`，业务文件无裸数字 |
