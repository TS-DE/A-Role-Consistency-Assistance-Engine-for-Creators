# 语料目录

## 放什么

```
data/corpus/
├── raw/          原文（.txt / .epub 转出的纯文本），**不入 git**（见 .gitignore）
├── quotes.json   20 句经典台词，英中双语 —— 已由 公开角色设定.txt 提供，待转成 json
└── settings.json 10 条核心设定 —— 同上
```

`raw/` 不进仓库的原因有两个：体积，以及版权。你自己本地留着即可。

## 版权这件事，别踩坑

- **英文原文**：柯南·道尔的作品已进入公有领域（美国 2023 年起基本全部可用，个别晚期篇目更晚；
  英国早已进入）。从 Project Gutenberg 取是安全的。
- **中文译本**：**译本有独立版权**，不是"原文公版所以译本也公版"。
  把一整本中文译本切块入库、再在回复里大段引用，是有风险的。
  稳妥做法：语料只用英文原文 + 你自己整理的中文**设定/台词摘要**（
  也就是 公开角色设定.txt 里那种量级，属于少量引用与分析，风险极低）。
- 这个项目只做**非公开的训练/求职演示用途**，不上线、不分发语料，风险进一步降低——但 README 里要写清楚这句。

## 入库前的清理（W1 第一天做，半小时）

1. 去掉 Gutenberg 的头尾版权声明段（开头约 20 行、结尾 LICENSE 段）。
2. 统一编码 UTF-8、统一换行 LF。
3. 按"篇"切分（每个短篇一个文件），文件名用篇名拼音，例如 `bohemia.txt`。
4. 保留原始行号或段落编号——后面检索命中时要知道引文出自哪个短篇的哪一段。
5. 删掉插图块与页码标记：`[Illustration: ... ]` 整段、`[Page 238` 这类行。
   `pg48320.txt`（#48320，*Adventures* 插图版）里这两类各有一百多处，
   不删会被切进 chunk，检索时变成噪音。

## 为什么按"篇"切分而不是一份大文件

因为**分块策略要跟语料结构对齐**。福尔摩斯短篇每篇 8k–12k 词，一篇之内是同一案件、
同一批人物，边界天然清晰。先按篇切，再在篇内做递归分块（按段落 → 按句），
比直接对 60 万词的整本做定长切块，检索质量高一个档。

> 这条直接进面试：*"我的分块不是定长切，是先按文档结构切、再按语义递归切。
> 因为我的检索单元是「一条设定」和「一段对话」，不是「500 个 token」。"*
